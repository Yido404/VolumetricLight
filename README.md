# Volumetric Light / 体积光

Minecraft **Java 1.20.1 + Forge 47.4.28+（47.x）**，使用 **Java 17**。

## 安装与开始

将 `releases/volumetriclight-1.20.1-0.1.1.jar` 放入游戏实例的 `mods` 文件夹。升级时先移除旧版 JAR，保留原世界存档。
多人游戏时，服务器和每位需要看到光束的玩家均安装同一版本。
不需要 Fabric API，也不需要额外光影包。

管理员（权限等级 2）按 **L** 或输入 `/vlight edit` 打开编辑器。
若 L 已被其他模组占用，可在游戏“选项 → 控制 → 按键绑定 → 体积光”修改。
单人世界需要开启作弊；服务器需获得 OP 权限。

1. 点击“新建灯光”，默认在玩家前方建立一盏**本地草稿**。
2. 在“光束”页设置位置，或点击“在世界中选取”后点选方块表面。
3. 拖动滑条观察效果，也可输入精确数值。右侧面板支持滚轮滚动。
4. “追踪”页可以固定照射、追踪指定玩家，或追踪进入区域的玩家。
5. “触发”页设置两个角点、玩家条件、触发模式、动作、持续时间和冷却。
6. 点击“应用”才保存并同步。“取消”放弃草稿；“重载”读取服务器最新配置。

中间是**当前世界的实际光束预览**。拖动中间区域转动观察方向，滚轮改变视野缩放；相机位置仍在玩家处。
“重置视角”朝向所选光束；“辅助线”显示光源、照射点和触发区域。
预览会暂时替换自己看到的这盏灯，其他玩家继续看到已保存的状态。
通常预览忽略区域条件，便于调光；“模拟进入”会在本地模拟进入、停留和离开，并执行当前触发规则。
“测试追踪”模拟移动目标，不会移动真实玩家或发送区域动作到服务器。

选取位置时面板暂时隐藏：左键点选 **64 格内**的方块表面，右键或 Esc 返回。
框选区域需要两次独立的左键按下；按住左键只记录一个角点。在第二次点击前取消，会恢复原来的两个角点。
区域按坐标范围包含玩家脚下位置，不会强制加载区块。
窄屏会把左侧列表收为“选择灯光”按钮；右侧出现细滚动条时可滚动查看更多设置。

## 光束参数

| 参数 | 单位与范围 |
| --- | --- |
| 光源 / 照射点 | 支持小数坐标；照射点决定方向，不限制射程 |
| 出光口半径 | 0–4 格；0 接近尖圆锥，大于 0 是截锥 |
| 张角 | 2–100 度，表示完整张角 |
| 射程 | 1–64 格 |
| 亮度 | 0–4 |
| 柔边 | 0.01–1 |
| 颜色 | 六位 RGB，例如 `#FFDEA8` |
| 转向平滑度 | 0.02–1；越大转向越平缓 |
| 区域大小 | 每个方向大于 0，最大 512 格 |
| 持续时间 / 冷却 | UI 使用秒；指令使用 tick，20 tick = 1 秒 |

指定追踪玩家或触发玩家在**首次绑定时需要在线**；之后保存 UUID，改名不影响原绑定。
离线、死亡或跨维度时暂停追踪，目标回来后恢复。
追踪触发者时按距离光源从近到远选取首位进入者，并保持到其离开；多人同刻进入使用 UUID 排序打破距离相同的情况。
旁观者和已死亡玩家不触发区域。

## 指令与命令方块

全部管理指令需要权限等级 2。除 `list` 外，编辑既有灯光时需在该灯光所在维度执行。
位置参数支持 `~` 相对坐标和 `^` 局部坐标。命令方块中可省略开头的 `/`。

```mcfunction
/vlight create stage
/vlight name stage 舞台主灯
/vlight source stage 10 80 10
/vlight target stage 10 64 20
/vlight radius stage 0.15
/vlight angle stage 30
/vlight range stage 24
/vlight brightness stage 1.2
/vlight softness stage 0.35
/vlight color stage FFDEA8
/vlight on stage
/vlight off stage
/vlight list
/vlight delete stage
```

`on` 立即开启；如果已配置区域自动化，后续新的区域事件会继续接管。
`off` 关闭总开关，区域事件不再点亮；再次执行 `on` 恢复。
反复执行相同的 `on` 不会新建灯光或反复写入世界存档。

```mcfunction
# 追踪指定玩家；支持 @p、@s 等单玩家选择器
/vlight track stage Steve
/vlight smoothing stage 0.25
# 恢复固定照射点
/vlight track stage off

# 任意玩家进入区域后亮灯 5 秒，冷却 2 秒
/vlight trigger stage box 8 64 18 12 68 22
/vlight trigger stage enter
/vlight trigger stage action pulse
/vlight trigger stage duration 100
/vlight trigger stage cooldown 40
/vlight trigger stage any

# 改为仅指定玩家触发
/vlight trigger stage player Steve
# 改为追踪进入区域的玩家
/vlight track stage trigger

# 区域有符合条件的玩家时亮，最后一人离开后灭
/vlight trigger stage presence
# 关闭区域自动化
/vlight trigger stage off

# 命令方块也能通过原版 execute 判断条件
/execute if entity @a[x=8,y=64,z=18,dx=4,dy=4,dz=4] run vlight on stage
```

进入动作还可选择 `action on`（进入后保持开启）或 `action off`（开始亮灯，进入后关闭）。
进入模式只在从外进入时触发一次；站在区域内不会反复触发，冷却结束也不会凭空新增一次进入。
存在模式只判断“是否至少有一名符合条件的玩家”，忽略持续时间和进入动作。
触发的临时计时与目标锁定不跨服务器重启保存；灯光配置、启用状态和区域会保存。应用配置修改会重新初始化该灯的临时触发状态。

编辑器“复制指令”会生成一条 `vlight import {…}` 完整配置指令，可粘贴到命令方块中。
同 ID 存在时更新配置，不存在时创建；只应用参数，不替换玩家背包或世界方块。
UI 和命令使用同一份世界数据；多人同时编辑时，旧草稿会被拒绝覆盖，须先重载。

## 渲染与首版限制

- 使用自带 GLSL 着色器在圆锥体内部采样散射，具备柔边、距离衰减和表面光斑。
- 从场景深度裁剪可见光束，另用光源方向的方块射线生成遮挡图。
- 遮挡图为 **16×16**，约每 250 ms 刷新，细杆、薄片、移动目标附近可能出现漏光或延迟；不包含实体投影。
- 使用碰撞形状判断遮挡；玻璃等材质没有独立透射模型。原版透明材质的深度行为也会影响遮挡。
- 每个世界最多保存 **64** 盏灯；每帧最多绘制附近 **8** 盏，编辑中的灯优先。
- 每个像素、每盏灯使用 64 次体积采样；高分辨率和多灯同时可见会增加 GPU 开销。
- 光束和光斑仅是视觉效果，不改变原版方块亮度、刷怪、作物或红石规则。
- 已在原版 Forge 渲染环境测试；尚未验证 OptiFine、Oculus 或其他会改写渲染管线的模组组合。

## 构建与验证

```powershell
$env:JAVA_HOME='你的 JDK 17 目录'
.\gradlew.bat build
# 自动建立专用测试世界，验证实际指令、UI、着色器并生成截图，然后退出
.\gradlew.bat runClient -PpreviewUI
```

成品位于 `build/libs/`。自检包含参数边界、NBT 与导出往返、区域进入边沿、冷却、多人锁定及指令结构。
图形测试额外验证重复开启的幂等性、并发修订冲突、实际指令执行、UI 应用与取消、界面控件边界以及开关灯截图亮度差异。
测试世界在 `run/saves/vlight-preview`，不访问其他游戏实例或存档。测试代码不包含在发布 JAR 中。
